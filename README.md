# 法律卷宗脱敏工具

面向律师的本地卷宗脱敏工具。把扫描件/拍照拼接的 PDF、Word 卷宗,在
**不联网、不出本机**的前提下自动识别并替换姓名、身份证号、电话、地址等
敏感信息,输出可以放心交给 Claude 等云端 AI 做资料整理、法律意见的纯
文本。

核心设计:检测和替换分离——本地大模型和正则/名单只负责标出敏感信息
的位置,替换本身由确定性脚本完成,原文除被替换片段外逐字不变,方便
审核追溯。任何检测环节置信度不够,都会拦截自动导出、转入人工审核。

## 安装(第一次用,在目标 Mac 上做一次)

```bash
bash setup_mac.sh
```

会自动装 Homebrew(如果没有)、Ollama、poppler、拉取本地模型
(约 4.7GB,需要网络),搭建 Python 虚拟环境,并跑一遍自带的测试作为
自检。装完把 `apps/打开脱敏工具.app` 拖到桌面或程序坞即可。

## 使用

1. 双击「打开脱敏工具」,会自动弹出浏览器网页。
2. 填案件名称(同一个案件每次填一样的名字),把卷宗文件拖进网页,
   点击「开始处理」。
3. 处理完自动跳到该案件的页面:
   - 没有发现需要人工核实的内容 → 直接显示「已导出」,去
     `~/法律脱敏工作台/案件_<名称>/03_已批准可上传/` 取文件即可。
   - 有需要确认的地方 → 页面列出每份文档的详情;涉及 OCR 识别质量
     的,页面上会直接显示对应原图,旁边是可编辑的文字框,对照检查、
     改错字、点「保存修改并重新处理」;确认无误后点「批准导出全部」。

**唯一规则:只把 `03_已批准可上传` 文件夹里的文件复制给 AI。**
其他文件夹(原始文件、转换后文本、候选脱敏文本)不要上传。

新案件建议先在案件文件夹的「案件人员清单.txt」里填入涉案姓名/公司名,
能明显提高识别准确率。

完整说明见 [使用说明.md](使用说明.md)。
识别规则的具体细节(哪些信息被识别、怎么识别、目前识别不到什么)见
[脱敏规则说明.md](脱敏规则说明.md)。

## 卸载

```bash
bash uninstall_mac.sh
```

会提示确认后删除:工具本身、`~/法律脱敏工作台/` 下的全部案件数据、
每个案件在钥匙串里的加密密钥、以及 Ollama 和已下载的本地模型。不会动
Homebrew 本体和 poppler(其他软件也可能用到)。

**如果是从更早的版本升级**(早期版本用的是「导入新卷宗」「批准并导出」
两个桌面小程序,而不是现在的网页界面):`uninstall_mac.sh` 会连同
`~/法律脱敏工具/` 整个文件夹一起删掉,里面不管是新版本还是旧版本的
程序都会被清理。**唯一需要手动处理的是桌面或程序坞上残留的旧图标**
(「导入新卷宗」「批准并导出」或「打开脱敏工具」)——这些只是快捷方式,
脚本删不到,直接手动拖进废纸篓即可。

## 项目结构

```
core/            核心逻辑(检测、合并替换、OCR、加密映射表、泄漏复查等),含单元测试
gui/             本地网页界面(Flask,只绑定 127.0.0.1)
apps/            双击运行的 App(AppleScript 编译)
tests/           pytest 测试
golden_corpus/   黄金语料回归测试用的示例文档 + 人工标注真值
scripts/         独立的回归/评测脚本(黄金语料召回率测试等,不属于 pytest 套件)
process_case.py  命令行入口(处理卷宗)
approve_export.py 命令行入口(批准导出)
setup_mac.sh     一次性安装脚本
uninstall_mac.sh 完全卸载脚本
```

跑测试:

```bash
source venv/bin/activate
python -m pytest tests/ -q
```

## 安全机制(会拦截自动导出、转入人工审核的情况)

除了敏感信息检测本身,以下几种情况也会拦截自动导出,要求先人工确认:

- **处理台账**:任何一页/一张嵌入图片在转换或 OCR 过程中失败(超时、
  文件损坏等),都会被记录下来并拦截导出——不会因为处理失败就悄悄
  跳过,当作"这一页没有敏感信息"。
- **表格/表单**:检测到疑似表格结构(PDF 用文字坐标网格判断、docx 用
  原生表格结构、图片用 OCR 坐标框判断)一律强制人工核对。原因是表格
  内容有一种自动检测抓不住的风险:同一行的姓名和身份证号如果被错误
  拼接到相邻的人身上,每一项单独看都合法、置信度也都正常,但对应
  关系是错的。
- **同名待确认**:「案件人员清单」里如果同一个姓名出现了不止一次,
  会被当作"本案可能有两个不同的人恰好同名"的信号拦截下来——系统目前
  没有能力自动区分两个同名的人,与其悄悄把他们当成同一个人处理,不如
  先让人工确认。
- **所有外部命令都有超时保护**(OCR、PDF 转换等),不会因为一份损坏
  或超大的文件把程序卡死无响应。
- **导出前独立复查**:在文件写入 `03_已批准可上传` 之前(不管是一键自动
  导出还是手动点「批准导出」),都会对最终文本做一次独立的二次扫描——
  重新跑一遍正则检测,并确认所有已识别的真实敏感值都不再出现在文本
  里。这一步不信任检测阶段自己的记录,专门用来兜住"检测环节本身有
  bug、漏掉了某处敏感信息但自己不知道"这种情况。发现问题会连同具体
  内容一起在审核报告里用 🚨 标出,并且这份文件不会被复制到
  `03_已批准可上传`。

## 黄金语料回归测试

`golden_corpus/legal/` 下是一组人工标注真值的示例法律文档(全部虚构,
用于测试),`scripts/golden_recall.py` 用真实本地模型跑一遍,检查身份类
实体(姓名/证号/电话/卡号)召回率是否达到 100%、一般类实体(地址/机构/
邮箱/出生日期/案号)召回率是否达到 85% 以上,同时列出"真值之外多替换
了什么"供人工判断是否过度脱敏。这是修改核心检测逻辑后建议跑一遍的
回归检查,不属于常规 `pytest` 套件(需要真实 Ollama 服务、跑一遍要几
分钟)。

```bash
source venv/bin/activate
python scripts/golden_recall.py                # 默认跑一遍
python scripts/golden_recall.py --repeat 3      # 同一批文档跑 3 遍,
                                                 # 暴露大模型偶发的不稳定
```

首次真实跑通的结果供参考(2026-08):身份类 27/27 = 100%,一般类
16/16 = 100%。同时也发现了两类目前会被过度脱敏、值得留意的情况,记在
下面的"已知局限"里。

## 已知局限

- 大模型识别不是百分百,案件人员清单仍是最可靠的一环。真实测试中曾
  出现过同一份文档里两个人名,大模型只识别出其中一个的情况——这也是
  为什么表格类内容会被强制人工审核,而不是完全信任自动检测。
- 法院/政府机关/银行名称目前也会被一并脱敏,偏保守但可能过度——
  黄金语料回归测试里实际出现过法院、开户行名称被替换的情况。
- **大模型偶尔会把"原告""被告""丙方"这类纯粹的法律角色称谓当成人名
  误判脱敏**——这是黄金语料回归测试真实跑出来的结果,不是猜测。目前
  没有专门修复,后果是候选文本里偶尔会多出一两个不必要的占位符,
  不影响安全性(不会漏脱敏),但可能让文档读起来有点别扭,人工审核
  时留意一下即可。
- OCR 在手机拍照类卷宗上的表现尚未用真实样本做过系统性基准测试;
  黄金语料目前也都是纯文本,还没有真实拍照/扫描样本。
- 表格检测目前只能识别"每个单元格被 OCR/文档结构识别为独立区域"的
  表格;如果整行表格内容被合并识别成一整行空格分隔的文字,这个检测
  抓不到,这种情况仍然依赖其他置信度信号或人工审核发现。
