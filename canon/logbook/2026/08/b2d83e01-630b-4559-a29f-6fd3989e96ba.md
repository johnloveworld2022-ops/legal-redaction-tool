## [2026-08-21] session b2d83e01 — build, harden, and audit the legal case redaction tool

**Intent.** Design, build (TDD), and progressively harden a local, offline-first PII
redaction tool for a lawyer's real Chinese-language legal casework — from initial
architecture review through a working GUI, a series of real-bug fixes, a Codex-informed
safety-hardening pass, a full multi-agent security/architecture audit with every critical
finding fixed, and initializing this bureau workspace for ongoing project knowledge tracking.

**Decisions.**
- Core architecture: detection and replacement are strictly separated — regex/lexicon/LLM
  detectors only ever report character spans, never rewrite text; a deterministic script does
  all substitution — implies dossier **Detection/Replacement Separation**.
- Long documents are split into ~3000-char overlapping chunks before LLM entity detection,
  after a real 42k-character PDF made the model abandon extraction and summarize the document
  instead — implies dossier **LLM Chunking**.
- Added birthdate (`YYYY年M月D日出生`, suffix-gated to avoid sweeping up ordinary dates) and
  court case-number regex detectors — both were previously uncovered by any detector, a real
  user-reported gap, not a design choice — implies dossier **Structured PII Detectors**.
- Adopted a multi-layer forced-review safety design per an external (Codex) architecture
  review: per-page/per-image processing ledger (a failed conversion blocks auto-export rather
  than being silently skipped), geometric table/form detection forcing human review
  (cell-swap risk no confidence score can catch), and duplicate-name detection in the case
  lexicon blocking auto-export (same-name-different-person has no algorithmic fix) — implies
  dossier **Safety Gates**.
- Added an independent leak-check re-scan of the final text before export (never trusts the
  pipeline's own bookkeeping), plus a golden-corpus recall-regression harness
  (identity-class entities gated at 100% recall, standard-class at 85%, methodology adapted
  from the closest comparable open-source tool) — implies dossier **Leak Check** and
  **Golden Corpus Regression**.
- Replaced two AppleScript drag-and-drop droplets with one local Flask GUI bound to
  127.0.0.1 only, so a flagged OCR page's saved image can render inline next to an editable
  correction textbox — implies dossier **GUI Architecture**.
- Created the `legal-redaction-tool` GitHub repo, verified no case data/secrets were tracked,
  then made it public at the user's request.
- Ran a full grill-style codebase review (recon + architecture + error-handling + security +
  testing agents in parallel, findings independently spot-verified by direct code reading and
  live reproduction before trusting them). Found 8 Critical findings, two of them directly
  exploitable path-traversal bugs with working reproductions. Because the repo is public, chose
  to fix all 8 before committing the report itself — publishing working exploit code for
  unpatched vulnerabilities would have been an irresponsible disclosure. All 8 fixed same-day,
  each via a red-test-first TDD cycle, the two most safety-critical additionally verified
  end-to-end against the real running server — implies dossier **Security Hardening (grill
  review)**.
- Scaffolded this bureau workspace (`canon/`, both software+story profiles) for ongoing
  project knowledge tracking — implies dossier **Bureau Workspace**.
